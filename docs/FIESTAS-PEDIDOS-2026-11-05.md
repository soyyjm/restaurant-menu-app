# 节日订餐：WhatsApp 发菜单 + 客人在线点餐 + 后厨统计（2026-11-05）

## 页面
| 页面 | 地址 | 谁用 |
|---|---|---|
| 后台管理 | `https://menusol.netlify.app/fiestas.html` | 员工（用菜单系统的同一个账号登录） |
| 客人点餐 | `https://menusol.netlify.app/p/<专属码>` | 客人，从 WhatsApp 消息打开，不用登录 |
| 演示版 | `fiestas.html?demo` | 先试用；数据只存在当前浏览器，不会写入数据库 |

## 文件
- `fiestas/menus.js`：4 天的菜单、儿童套餐、价格、截止日期。**定稿后只需要改这一个文件。**
  菜品的 `key`（例如 `sopa25`）会存进客人的点餐记录，客人开始点餐后不要再改 key。
- `fiestas/img/<key>.jpg`：菜品照片（640px）。新菜只要放一张同名照片；没有照片时显示文字卡片。
- `fiestas/api.js`：数据读写（正式版用 Supabase；`?demo` 用本机存储）。
- `pedido.html`：客人页面，支持西班牙语和加泰罗尼亚语。
- `fiestas.html`：后台，包括订台名单、后厨汇总、按桌明细，可以打印和导出 Excel。
- `supabase/005_fiestas_pedidos.sql`：建表和客人接口；`supabase/005_simulation.mjs` 是本地模拟测试，28 项全部通过。
- `netlify.toml`：新增 `/p/*` → `pedido.html`。

## 上线步骤（一次性）
1. Supabase Dashboard → SQL Editor → 粘贴 `supabase/005_fiestas_pedidos.sql` → Run。
   需要先执行过 004（会用到 `public.set_owner_id`）。脚本在一个事务里，可以重复执行。
2. 部署到 Netlify（和平时一样推送或上传）。
3. 登录 `fiestas.html`，录入一个测试订台，点“预览”，以客人身份点一次餐，确认后台能看到，再删除测试订台。

## 安全设计
- 两张新表 `fiesta_bookings` 和 `fiesta_orders` 只有登录的店主账号能读写（和 004 一样），未登录用户没有任何表权限。
- 客人只能通过两个函数访问：`fiesta_booking(token)` 和 `fiesta_submit(token, …)`。
  专属码是 128 位随机数，一个链接只能看到和修改自己那一桌；返回的数据不包括电话和内部备注。
- 服务器会检查每道菜的份数之和是否等于人数，过了当天（马德里时间）或员工点了“截止点餐”之后就拒绝提交。

## 流程
1. 名单确定后：在后台录入（单条录入，或从 Excel 复制粘贴，列的顺序为：姓名、电话、大人、小孩、桌号）。
2. 每一行点绿色的“发送 WhatsApp”：WhatsApp 会打开，并填好这位客人的消息和链接，按发送即可。
   9 位西班牙号码会自动加 34 区号，外国号码请带 + 号。
3. 客人为每位大人和小孩选择头道、主菜和甜点的数量，可以填写过敏信息，截止前可以随时修改。
4. 后厨汇总显示每道菜的总份数（大人和儿童分开）、Pica-pica 套数（每桌按每 4 人一套计算）和过敏清单；
   按桌明细显示每桌点了什么，以及 Solomillo 等菜品的补差价。都可以打印或导出 Excel。
5. 订台改了人数时：旧的点餐会标记为“人数已变，需重填”，不计入统计，客人重新打开链接后会被提示重新选择。
