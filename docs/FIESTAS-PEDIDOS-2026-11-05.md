# 节日订餐：WhatsApp 发菜单 + 客人在线点餐 + 后厨统计（2026-11-05）

## 页面
| 页面 | 地址 | 谁用 |
|---|---|---|
| 后台管理 | `https://menusol.netlify.app/fiestas.html` | 员工（用菜单系统的同一个账号登录） |
| 客人点餐 | `https://menusol.netlify.app/p/<专属码>` | 客人，从 WhatsApp 消息打开，不用登录 |
| 演示版 | `fiestas.html?demo` | 先试用；数据只存在当前浏览器，不会写入数据库 |

## 文件
- `fiestas/menus.js`：4 天的菜单、儿童套餐、价格、截止日期。**定稿后只需要改这一个文件。**
  菜品的 `key`（例如 `sopa25`）会存进客人的点餐记录，客人开始点餐后不要再改 key。
- `fiestas/img/<key>.jpg`：菜品照片（640px）。新菜只要放一张同名照片；没有照片时显示文字卡片。
- `fiestas/api.js`：数据读写（正式版用 Supabase；`?demo` 用本机存储）。
- `pedido.html`：客人页面，支持西班牙语和加泰罗尼亚语。
- `fiestas.html`：后台，包括订台名单、后厨汇总、按桌明细，可以打印和导出 Excel。
- `supabase/005_fiestas_pedidos.sql`：建表和客人接口；`supabase/005_simulation.mjs` 是本地模拟测试，28 项全部通过。
- `netlify.toml`：新增 `/p/*` → `pedido.html`。

## 上线步骤（一次性）
1. Supabase Dashboard → SQL Editor → 粘贴 `supabase/005_fiestas_pedidos.sql` → Run。
   需要先执行过 004（会用到 `public.set_owner_id`）。脚本在一个事务里，可以重复执行。
2. 部署到 Netlify（和平时一样推送或上传）。
3. 登录 `fiestas.html`，录入一个测试订台，点“预览”，以客人身份点一次餐，确认后台能看到，再删除测试订台。

## 安全设计
- 两张新表 `fiesta_bookings` 和 `fiesta_orders` 只有登录的店主账号能读写（和 004 一样），未登录用户没有任何表权限。
- 客人只能通过两个函数访问：`fiesta_booking(token)` 和 `fiesta_submit(token, …)`。
  专属码是 128 位随机数，一个链接只能看到和修改自己那一桌；返回的数据不包括电话和内部备注。
- 服务器会检查每道菜的份数之和是否等于人数，过了当天（马德里时间）或员工点了“截止点餐”之后就拒绝提交。

## 流程
1. 名单确定后：在后台录入（单条录入，或从 Excel 复制粘贴，列的顺序为：姓名、电话、大人、小孩、桌号）。
2. 每一行点绿色的“发送 WhatsApp”：WhatsApp 会打开，并填好这位客人的消息和链接，按发送即可。
   9 位西班牙号码会自动加 34 区号，外国号码请带 + 号。
3. 客人为每位大人和小孩选择头道、主菜和甜点的数量，可以填写过敏信息，截止前可以随时修改。
4. 后厨汇总显示每道菜的总份数（大人和儿童分开）、Pica-pica 套数（每桌按每 4 人一套计算）和过敏清单；
   按桌明细显示每桌点了什么，以及 Solomillo 等菜品的补差价。都可以打印或导出 Excel。
5. 订台改了人数时：旧的点餐会标记为“人数已变，需重填”，不计入统计，客人重新打开链接后会被提示重新选择。

## 特殊需求（2026-11-05 补充）
原则：特殊需求都由员工在后台处理，客人只负责说明。

- **客人端**：每道菜最后都有一个 “Otra opción / petición especial” 选项，和普通菜一样计入份数，所以“奶奶不吃头道”也能凑齐份数提交。
  选了这一项后，必须在“Alergias, intolerancias o peticiones especiales”里写明需求，否则不能提交。
- **后台**：这桌显示“有特殊需求待处理”，后厨汇总顶部也会提醒。点“改点餐”打开编辑器，可以：
  - 改成**半份**（每道菜都有“整份 / 半份”两个计数）
  - 改成**不要这道**
  - 加一道**菜单外的菜**（输入菜名）
  - 改完把“其他需求”减到 0，保存。
  保存后这桌默认**锁定**，客人打开链接会看到“El restaurante ha confirmado vuestro pedido”和最终内容，不能再改，避免覆盖员工的修改。
  需要让客人重新选时，点“解锁”。“重新开放点餐”整天解锁时，员工已确认的桌会保持锁定。
- **人数变化**：员工改人数后，可以马上在编辑器里调整点餐；也可以让客人用原链接重新选。客人页面会保留之前的选择，只需要补上或减掉差额（多出的会提示 “Sobran N platos”）。
- **代客点餐**：客人打电话点的，也可以由员工直接在后台录入（“代客点餐”）。
- **后厨汇总**：每道菜显示整份数，加上“+ N 个半份”；菜单外的菜、“不要这道”和“待员工确认”分开列出。导出的 Excel 多了一列 “Especiales”。
- 数据格式：特殊项和普通菜放在同一个计数表里：`none`、`otro`、`<菜>~h`（半份）、`x~<菜名>`（菜单外）；员工改过的点餐带 `staff_at` 标记。数据库不需要改动。

## 2026-11-06 补充
### 价格说明
客人页面的介绍和“Otra opción”选项里都写明了：这是固定价格的套餐，要半份或不要某道菜，价格都不变（西班牙语和加泰罗尼亚语都有）。

### 打印和 Excel 用西班牙语
- 后台屏幕上仍然是中文。“后厨汇总”和“按桌明细”打印时会自动换成西班牙语版本（按钮或 Ctrl+P 都一样），标题写 “Resumen de cocina / Detalle por mesa”。
- 导出的 Excel 也是西班牙语，包括状态列。
- 员工写的内部备注（例如“已付定金”）不会出现在打印单和 Excel 里，只在后台屏幕上显示。

### 大桌分享链接（需要先运行 `supabase/006_fiestas_grupo.sql`）
- 如果订台人数在 6 人以上，主办客的页面会显示 “¿Mesa grande? Que cada uno elija desde su móvil”，可以把**分享链接** `/g/<码>` 通过 WhatsApp 发给同桌的其他人。
- 同伴打开后填写自己的名字，选择要替几个人点（比如自己一家），然后选菜、提交。同伴可以用同一部手机回来修改或删除自己的选择。同伴只能看到自己的选择，看不到电话，也看不到别人点了什么。
- 主办客的页面会列出所有人的选择，显示“已选 X / 共 N 人”，点 “Pasar estas elecciones al pedido” 就会把大家的选择汇总进订单。大家写的过敏信息会带上名字一起并入。补上没选的人以后，由主办客提交。餐厅仍然是每桌收一份订单。
- 主办客提交后如果还有人修改，主办客页面会提示 “Hay elecciones nuevas…”，点一下就能更新。
- 后台：订台名单显示“分享链接 X / N 人已选”；按桌明细（打印版也有）多了“按人”一栏，列出每个人点了什么，方便上菜。
- 安全：分享链接和主办客链接是两个不同的码，同伴拿不到主办客的链接，也改不了整桌的订单。每桌最多 40 份同伴提交；截止或锁定后，同伴也不能再改。
- 数据库：新增 `fiesta_shares` 表（只有店主能读写），`fiesta_bookings.share_token` 字段，以及 3 个函数；`fiesta_booking` 会多返回同伴的选择。本地模拟测试见 `006_simulation.mjs`（26 项全部通过）。
- 注意：如果以后重新运行 005，需要再运行一次 006（因为 005 会把 `fiesta_booking` 恢复成旧版本）。
